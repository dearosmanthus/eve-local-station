# 0.5.0 星图交互与本地详情

本版集中调整星图：星点变小，拖动和缩放时保留清晰的星点、连线与文字；补充星系详情、
相邻星系和路线操作。装配计算引擎与五个 PB2 数据文件没有改变。

## 绘制与操作

普通星点半径为 1.0 dp，重点星点半径为 2.8 dp，选中圆环半径为 5.5 dp。这些尺寸按屏幕
坐标绘制，放大地图时不会继续膨胀。点击使用屏幕距离寻找附近星系，命中范围不会随着
地图缩放变大或缩小。

平移和双指缩放直接通知画布重绘；地图几何和空间索引只在切换星域或数据时建立。星门
路径预先生成，局部视图只查询视窗附近的点与线。低于 0.7 倍且可见点超过 500 个的全图
概览使用预存的星门路径和三组安全等级点云批量绘制，再叠加重点、路线和绕行标记。
即使一条星门线的两个端点都在屏幕外，只要连线穿过视窗就仍会绘制。

文字使用最多 256 条的布局缓存。选中星系和路线端点优先显示，普通名称依据缩放级别、
可用空间与重叠情况显示；全图概览不会铺满普通星系名称。名称与星门连线可以分别开关。
新增放大、缩小和重置视角按钮，定位使用短暂平移缩放过渡，开始手势时停止过渡。

区域切换会清理当前区域以外的选择。路线摘要或地图可用高度改变时，保留原有中心与
缩放，不重新跳回全图。详情可以复制英文星系名、查看所属星域、设置绕行，或直接定位
相邻星系。全部操作使用本地静态资料，不增加账号、网络请求或设备权限。

路线支持交换起终点、复制英文路线和查看整条路线。查看跨星域路线时切换到星门网络并
适配全部路线；同一无星门星系的合法零跳路线仍能定位到该星系。

## 星系详情的数据来源

详情补充所属星座、行星数量和恒星光谱。这些字段由已有的官方 SDE 3494416 构建，
本版没有额外下载游戏数据，也不把缺失字段补成推测值。

| 字段 | 官方来源 | 本地覆盖 |
| --- | --- | ---: |
| 星座 | `mapSolarSystems.constellationID` 对应 `mapConstellations` | 8490 个星系，1184 个星座 |
| 行星数量 | 明确提供的 `mapSolarSystems.planetIDs` 数组长度 | 8088 个星系 |
| 恒星光谱 | 星系的 `starID` 对应 `mapStars.statistics.spectralClass`，并核对所属星系 | 8089 个星系 |

1184 个星座均有官方中文名称，部分名称与英文相同。行星列表缺失与显式空列表分别保留
为未知和零；缺失光谱保持未知。例如 Jita 属于 Kimotoro / 木本呂星座，8 颗行星，光谱
F1 V。星门数量和可达性仍使用原有静态星门数据；这些资料不代表当前通行安全。

## 独立正确性与性能测量

`app/test/map_performance_test.dart` 的 3 项真实数据检查通过：

- 114 个星域投影合计覆盖全部 8490 个星系；默认星门网络覆盖 5268 个有静态连接的星系。
- 四种缩放的可见点、相交星门和屏幕点击结果与完整扫描一致，包含两个端点都在屏幕外的真实星门线。
- 重复画面复用文字布局，拖动期间缓存保持上限，离开画布后释放布局资源。

另有 9 项画布几何与 widget 检查通过，覆盖 0.25 / 1 / 10 倍缩放下的星点、选中环、星门
和路线像素尺寸，20 dp 屏幕命中、重叠选择顺序、穿屏连线、名称避碰、缓存释放、全图
名称层级、路由与绕行集合快照，以及只改变变换时重绘且卸载后解除监听。批量分支额外
核对三次点云调用与重点标记叠加，并检查其像素外缘与局部视图一致。独立检查发现
并修正了三维矩阵 Z 轴使缩小视图被误判为一倍缩放的问题；普通名称层级、线宽补偿和
缩小按钮均使用二维缩放。

下面为 Windows x64、Flutter 测试环境中的 CPU 与 Canvas 指令录制测量。数据来自
Tranquility SDE 3494416，Dart 3.9.2；视窗为 390 × 560 dp，以 Jita 为中心，并绘制
Jita–Amarr 路线。投影与索引建立中位数为 13.640 ms（8 次），可见范围查询中位数为
0.513 ms（128 次），屏幕命中检测中位数为 0.026 ms（64 次）。

| 缩放 | 视窗内星系 | 与视窗相交的星门 | 拖动录制中位数 | 拖动录制 P95 |
| --- | ---: | ---: | ---: | ---: |
| 0.25 倍，全图 | 5268 | 6989 | 0.855 ms | 1.174 ms |
| 4 倍 | 293 | 455 | 1.528 ms | 2.896 ms |
| 10 倍 | 66 | 125 | 0.313 ms | 0.440 ms |

每种缩放录制 48 步平移。可见数量使用严格视窗查询；实际画笔另保留少量边缘缓冲。
全图仅缓存两个重点名称，整段测量最多缓存 164 条布局，没有重复驱逐布局。

开发过程中，批量绘制前的同机同脚本全图录制中位数为 9.215 ms；最终实现为 0.855 ms。
这两个开发快照之间也缩小了普通星点，不能把结果当作单一改动的严格对照实验。原始
前后记录分别保存在开发目录 `work/map-host-benchmark-0.5-before-batching.json` 与
`work/map-host-benchmark-0.5.json`；交付以本页最终数值为准。

这些数据不是 Android 手机帧率，也不包含 GPU 栅格化、合成、手势输入延迟或手机字体
开销。测试使用主机 debug 模式和测试字体，未与已发布旧版比较，也不据此承诺特定 FPS。
不同主机和并行构建负载会影响耗时；测试只约束正确性、缓存上限和工作量，不设置不稳定
的毫秒通过门槛。可运行上述测试复核，设置环境变量 `ELS_MAP_BENCHMARK` 可另存 JSON 报告。

最终完整测试结果、预览、APK 摘要和离线审计见 [BUILD_REPORT.md](../BUILD_REPORT.md)。
原有 132 项 pyfa 对照仍对应未改变的计算引擎和 PB2 数据，本版不扩大其验证范围。
